# 桌面重构设计

业务字段及精确公式见 [requirements.md](requirements.md)。本文描述批准的实现目标与验证方法，不代表测试已经通过。

## 架构和运行环境

新程序分为 domain/ 纯业务规则、ui/ Vue 界面、desktop/ Electron 主进程/preload/数据库 worker/打印；保留 src/ 作为旧行为证据。固定 Electron 22.3.27、Vue 3.5.13、Element Plus 2.9.5、better-sqlite3 8.7.0；Vite 6.2.6 和 TypeScript 用于开发构建。渲染产物明确面向 Chrome 108，桌面代码遵守 Node 16 API 范围；开发机器较新的 Node 不意味着目标运行时支持那些 API。

目标是 Windows 7 SP1、10、11 x64。Electron 22 已结束维护，固定该版本是旧系统兼容的明确限制，不能承诺现代安全更新或仅凭版本号宣称 Windows 7 验收通过。开发工具 Node 与 Electron 自带 Node 是独立环境。

UI 通过 context isolation 下有限 preload 接口访问能力，不直接访问数据库或文件系统。主进程校验参数并协调窗口、目录选择、打印和 worker。全部数据库读写和迁移在专用 worker 中执行，错误返回可显示信息，防止 Promise 永不结束及主进程阻塞。

## 数据和接口

订单头与明细分开存储：头含唯一 orderId、createAt、orderForm、totalPrice、detailForm、原始扩展字段；明细按订单及位置保存原始计算结果快照。计算记录和设置独立保存；不能用新设置重算历史。索引支持 orderId 排序、按订单及位置读取明细。创建/删除订单及其明细、迁移完成标记均使用事务保证一致。

| preload 方法 | 输入及输出 |
| --- | --- |
| getStatus | ready、needsMigration、error控制启动门禁；capabilities.recentOrderInputs确认主进程支持最近输入，界面同时检查preload方法，兼容开发热更新后的旧窗口 |
| selectLegacyDirectory / initializeEmpty | 选择旧库迁移或明确初始化空库 |
| getSettings / saveSettings | 读取/保存完整设置 |
| saveCalculation | 保存输入和计算结果快照 |
| nextOrderNumber | `{date,index}` → `{no,index}`，只碰撞递增 |
| createOrder | 完整订单含明细 → orderId |
| saveOrderDetail | `{orderId,detailForm,orderForm?}` → 完成状态；可选orderForm更新销售表头六项及整单备注orderNote，订单头、摘要、搜索索引同事务提交 |
| listOrders | `{page,pageSize,search}` → items、过滤 total、page、pageSize |
| getOrderHeader | orderId → 不含 sizeList 的头及 itemCount |
| listOrderItems | `{orderId,offset,limit}` → 当批 items 和 total |
| deleteOrder | orderId → 删除完成状态 |
| printOrder | `{orderId,kind,itemIndex?}`，kind=sale/production/label |

列表摘要只含 orderId、createAt、orderForm、totalPrice、itemCount，不含全量明细。历史页仅左侧订单列表分页；右侧按所选订单分批读取全部明细后完整渲染，不提供明细分页，仅缓存当前订单。计算页仍使用虚拟列表。搜索在存储/迁移时按 JavaScript toUpperCase 生成各 orderForm 值的搜索数据；SQL 保留字段边界、连续子串和字符语义，防止跨字段拼接假匹配。参数化 COUNT 和分页查询使用同一条件。任意子串通常不能靠普通 B-tree 加速，必须实际测量十万订单搜索，不能以“建索引”宣称无延迟。

## 迁移、事务与恢复

新库放在 app.getPath('userData')/db，不相对安装目录写库。旧来源是 src/renderer/lib/nedb.js:19 的 ../../Tang/*.db；除自动发现外支持目录选择。先复制旧文件，原库只读；逐行流式读取副本，按 NeDB 日志规则处理同 _id 更新、删除、索引元数据与日期编码，不把百万明细装入渲染进程。

迁移事务保存订单、明细、计算记录、设置及未知旧字段，完整快照用于比较。核对数量、顺序、编号、日期、金额、订单头和明细字段；全部一致才提交完成标记。损坏 JSON、结构错误、主键冲突立即停止并回滚，提示文件及原因，保留备份。不得跳过坏行、覆盖已有目标数据或将失败后的空库当作迁移成功。重启依据已提交标记防止重复导入；失败可在处理源数据后重试。

迁移仅为升级流程，不新增通用导入导出。卸载不自动删除用户数据。活跃 SQLite 的 WAL 一致性必须由维护流程保证，不把简单复制运行中数据库称作可靠备份功能。

## 页面与状态

四个页面采用浅灰底、白色工作区、深绿色主操作，最小 1024×600。导航清晰固定；宽表在工作区内滚动，所有页面有空态、加载态及失败反馈。

计算页分洞口、产品、计价/备注输入，展示随墙体与设置变化的公式；下方提供清单移除和创建订单。设置页仅展示 11 个生效参数及型号/颜色/材质选项。

当前订单只有本会话创建后才有数据，含销售、生产、标签；七项销售补充由当前订单状态持有，保存与销售打印等待持久化成功。历史左列表右单据，300ms 搜索防抖、左侧每页 100 条、右侧全部明细、忽略过期请求；历史只读展示销售、生产、标签三个页签（2026-11-17用户追加，取代原无标签入口约束）。标签从已保存订单头和明细快照还原，复用当前订单的八行卡片；逐张打印转发零基itemIndex，使用现有打印IPC，不新增存储表或重新计算。标签在右侧容器内滚动，无分页。删除通过确认后提交，明确生产单及标签一并删除且无法恢复，成功更新页码和选择。

后续明确修正上段“历史只读”：历史销售单七项补充资料开放编辑，完整展示与当前订单相同的三行表格及默认值，已保存值（包括空值）优先。通过原saveOrderDetail接口保存，打印前等待保存成功；失败保留输入并阻止打印。保存后清理该单缓存并同步当前订单同编号的detailForm，防止后续覆盖。生产、标签保持只读。

历史页签由 HistoryView 持有，通过 `v-model:tab` 传入 OrderView；列表点击、搜索、空结果恢复和分页切换保留当前页签，订单加载导致详情组件重建时不重置。首次打开历史默认销售单，当前订单创建时仍默认销售单。

计算清单、未提交表单、当前选择仅会话内存，不新增重启恢复。已计算与已生成订单保存独立快照，设置变更不能改变历史尺寸或金额。

## 打印

页面及独立打印窗口共用 OrderDocument/LabelDocument 单据组件；打印从持久化快照生成内容，转义用户文本，等待布局完成再调 Electron 打印。销售/生产 A4 纵向，每 12 条明细使用一个独立固定列宽表格，多页重复表头且不带应用导航，长文本允许自然跨页；整张订单仍是一次打印任务，末页才展示销售汇总。分块读取后一次提交渲染，避免超长单表分页的内存膨胀。标签逐条打印，共八字段，沿用内容自适应布局与 2mm 边距，纸张使用打印机设置，不推测标签纸宽高。驱动的最小纸张、不可打印区域、中文字体、取消和失败必须实机验证；窗口打开不表示纸张已输出。

## 验证门槛

1. 旧代码特征测试：四种墙体、全部尺寸参数、字符串数字、空单价、零金额、小数截断、UTC+8 边界、编号碰撞和 999→1000；快照隔离及设置不重算。
2. 数据库：CRUD、唯一键、级联删除、SQL 分页、Unicode 子串及字面百分号/下划线；NeDB 更新/删除/日期/索引日志、损坏回滚、重复迁移、源文件不变及完整快照比较。
3. UI：1024×600 四页面完整操作，新启动当前订单空态、键盘操作、失败保留表单、删除确认、历史销售补充编辑保存、设置、11 列生产单及八行标签。
4. 打包：Windows x64 安装/卸载、非管理员 userData、中文路径、离线启动、原生模块 ABI。数据库测试使用 tools/electron-node.cjs 在 Electron 的 Node 下运行，不能用主机 Node 的原生测试替代。
5. 性能：双核/4GB/SSD 基线，10 万订单/100 万明细、单订单 1 万明细；记录启动、分页、搜索、整单详情、保存、迁移耗时、峰值 RSS 及 UI 响应。高配开发机结果不代表最低配置。
6. 真机：Windows 7 SP1/10/11 x64，物理 A4/标签打印机的长单分页、裁切、边距、中文和驱动失败/取消。

实际执行结果写入进度记录。缺少真机、物理打印机或最低配置测量时明确标为未验证；构建、类型检查、模拟测试不能替代这些证据。
