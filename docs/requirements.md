## 精确计算、输出和清单

令 W=洞口宽，H=洞口高，T=墙厚，D=门厚，S=当前保存设置。保留原生减法、乘法和 parseFloat 语义，不统一替换为取整或金额分值运算。

| 输出 | 规则 |
| --- | --- |
| 宽差量 dw | single 使用 S.singleWall；double 使用 S.doubleWall；其他使用 S.doorWidthDiff |
| 高差量 dh | up 使用 S.upWall；其他使用 S.doorHeightDiff |
| 门板宽 B / 高 L | `W - dw` / `H - dh` |
| holeSize | 原始输入按 `W + '*' + H + '*' + T` 拼接 |
| doorSize | `B + '*' + L` |
| woodSize.hengFang | `(B - parseFloat(S.woodWidthDiff)) + '*4'` |
| woodSize.shufang | `(L - parseFloat(S.woodHeightDiff)) + '*2'` |
| 扣板截面 C | `parseFloat(T) - parseFloat(D)` |
| coverSize.widthOne | `C + '*' + (parseFloat(B) + parseFloat(S.koubanWidth)) + '*1'` |
| coverSize.widthTwo | `C + '*' + (parseFloat(L) + parseFloat(S.koubanHeight)) + '*2'` |
| coverSize.heightOne | `parseFloat(B) + parseFloat(S.lucaiWidth)` |
| coverSize.heightTwo | `parseFloat(L) + parseFloat(S.lucaiHeight)` |
| singlePrice | `price * number`，不按单位/尺寸额外计价 |
| createDate | 本次计算的毫秒时间戳 |

墙体差量替换默认差量，不叠加。`*4`、`*2`、`*1` 是尺寸字符串中的数量标识，不把长度乘四或乘二；铝材是两个独立长度，不相除。默认设置 W=900/H=2100/T=240/D=45、无墙体：门板 `820*2060`，横方 `760*4`，竖方 `1930*2`，扣板 `195*827*1` 与 `195*2063*2`，铝材 950 与 2135。

计算结果包含以上输出及全部原始输入，深拷贝后置于当前清单首条，并保存计算记录。表格显示洞口/墙体、门板、横方/竖方、扣板/铝材、开向、型号、颜色、材质、单位、数量、单价、备注。移除只删清单对应行；重置恢复输入初值并清空清单，不删除数据库记录。空清单不能创建订单。设置变化不重算既有清单或历史快照。

## 金额与日期格式

formatMoney 忠实保留旧字符串算法：假值（包括数值 0、空值）返回空字符串；其余先转字符串，从整数部分右侧每三字符插逗号；无小数点追加 `.00`，有小数点先补零再截取小数点及两字符，**截断而非四舍五入**。例如 1234.567 → `1,234.56`，1.2 → `1.20`，数值 0 → 空，字符串 `'0'` → `0.00`。不以 Intl 格式替代；负号、科学计数法等边界按旧函数特征测试。行金额原始展示与合计格式化须区分。

日期假值返回空；其余固定 UTC+8，默认 `YYYY-MM-DD`，编号 `YYYYMMDD`，分组 `YYYY年MM月DD日`。不随电脑时区改变日期。

## 历史记录

orderId 降序，每页 100 条，按所展示记录日期分组。选择后按需加载订单头和明细。只有销售/生产两个页签；销售可打印、删除，生产可打印，均不可编辑。删除前确认对应生产单一起删除；取消无副作用，成功后更新选择、页码、总数。

搜索仅匹配 orderForm 各字段的值，不扩展到计算结果、行备注或 detailForm。每个值转字符串，使用 JavaScript toUpperCase，再对同样大写的词做连续子串匹配；搜索去首尾空格，300ms 防抖，条件变化回第一页。不能用 ASCII-only SQL NOCASE 替代 Unicode 大写，不能使 `%`/`_` 变为通配符。SQL 过滤总数与分页条件必须一致；只向 UI 返回当页摘要，不全量加载订单/明细，忽略过时搜索响应。
