版本：2026-11-17。依据：[业务需求](../requirements.md)、[设计](../design.md)、保留的 `src/` 旧代码及当前会话明确追加要求。日期分组保留，历史列表项只显示订单编号和客户名称；复选框和分页保留。新要求优先于文档内已注明被取代的旧方案。

本清单以业务场景计数；一个场景可以由多个参数化断言或多段测试共同验证，不能与 Node 的测试条数相加。执行结果、限制和原始证据见 [测试报告](test-report.md)。所有创建、删除、失败注入与迁移都使用测试专用临时目录。

## 执行约定及追溯

- `B`：`tests/business.test.ts`，直接执行保留旧版公式作为兼容对照。
- `R`：`tests/requirements.test.ts`，根据文档手工计算期望值，避免新旧代码存在相同错误却通过。
- `S`：`tests/storage.cjs`；`RS`：`tests/requirements-storage.cjs`；均通过 `tools/electron-node.cjs` 在目标 Electron 的 Node 下执行真实 SQLite。
- `E`：`tests/electron.cjs`；`U`：`tests/requirements-ui.cjs` 中 UI-01～UI-11；`H`：`tests/history-batch-delete.cjs`；均使用真实应用、preload、IPC 和数据库。
- `D`：`tests/documents.cjs`；`P`：`tests/print.cjs`；`PDF`：`tests/pdf-output.py`。只替换物理打印交接；实际模板、窗口、排版、PDF 生成与独立解析仍执行。
- 下表“步骤”同时给出关键输入；默认尺寸 W/H/T/D 为 900/2100/240/45，默认设置来自需求文档。P0 为数据或核心流程，P1 为功能与性能，P2 为环境验收。
