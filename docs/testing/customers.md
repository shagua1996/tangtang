# 客户名称记忆、删除与筛选实施记录

依据：2026-11-18 用户批准的客户功能计划；目标分支 codex/desktop-ui。

任务：存储与 schema 2 升级 → IPC 与客户筛选交互 → 自动化回归 → 整体审查。后续布局调整为订单列表上方下拉筛选，移除独立客户栏。

关键约束：客户按 trim 后的名称精确归类；删除名称保留订单；仅创建或明确改名恢复已删除客户；客户 50 条分页，输入候选 20 条，订单 100 条分页；计算、打印业务保持原规则。

当前进度：存储、IPC、界面、文档及整体审查完成，完整回归通过；未提交或推送。

接口衔接：创建订单客户候选和历史客户下拉共用 listCustomers；createOrder/saveOrderDetail 事务维护客户及订单关联；客户删除不改订单头；历史保存/打印后刷新列表。

## 2026-11-18 验证结果

- `pnpm test`：58项业务/能力测试及6组SQLite存储测试全部通过（含客户专项）。
- `pnpm test:e2e`：构建及13个Electron测试入口全部通过，包括客户流程、旧preload/旧主进程、批量删除、历史销售/标签、三种单据打印及10,000明细回归。
- 客户专项在真实Electron数据库写入10,000个客户后，查询总数为10,000，页面仍只渲染50个客户；快速查询最终仅显示目标客户。强制延迟旧订单IPC响应后，界面仍保持最新选中客户。
- 候选IPC读取失败时手动创建成功；客户末页唯一名称删除后自动回到上一页；1024×600窗口外层没有水平或垂直溢出。截图：`test-results/customers-history.png`（忽略文件）。
- 存储专项10,000客户多次有界查询合计约3–6ms，仅代表本机单次测试，不是所有硬件性能保证。
- `git diff --check` 与相关JavaScript语法检查通过。工具输出有现有 Node DEP0190 和 npm环境配置提示；无功能测试失败。
- 打印验证覆盖真实打印窗口内容及PDF生成，未连接物理打印机；本次未生成安装包。
