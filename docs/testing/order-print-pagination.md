# 销售单、生产单打印分页回归

业务对应：`docs/requirements.md`「2026-11-19 销售单与生产单按纸张高度分页」，原销售/生产表格及 `ui/PrintView.vue` 打印入口。修复前固定每12条换页，18条销售明细实际生成两页PDF。

## 用例

| 场景 | 预期 |
| --- | --- |
| 18条普通销售/生产明细 | A4纵向一页完整显示，销售尾部资料保留 |
| 60条普通销售/生产明细 | 按实际高度分页，前页接近底部可打印边界；不固定每12条换页 |
| 60条混合行高明细，每3条含一个四行型号和备注 | 按换行后的真实高度计算；完整行换页，无丢失/重叠/越界 |
| 销售尾部资料 | 合计、整单备注、付款信息、销售单位、收货人仅输出一次；必要时自然跨页 |
| 10,000条生产明细 | 单次打印任务完成，序号1至10000连续，最后一条备注存在，各页表头可见 |
| 取消打印 | 打印窗口释放，之后仍能打印 |
| 当前/历史页面和打印 | 内容、合并单元格一致；页面及标签原样式保持 |

## 执行

```powershell
pnpm.cmd build
pnpm.cmd test
node tests/print.cjs
python tests/print-pagination.py
node tests/documents.cjs
node tests/label-print-layout.cjs
```

PDF独立校验需要PyMuPDF，可安装到不入库的 `test-results/pdf-tools`。`tests/print.cjs` 仅替换操作系统打印交接，用真实Electron打印窗口、数据读取、模板和Chromium PDF排版；不会消耗纸张。PDF脚本核对序号、字段、纸张尺寸、文字边界与前页利用率。结果在 `test-results/PAGINATION-*.pdf`、对应PNG及 `pagination-proof.json`。

2026-11-19验证：18条销售/生产均1页；60条普通销售2页、生产3页；10,000条生产明细435页，PDF生成约11秒。真实打印机和驱动仍需现场复验；此记录不代表物理打印完成。

构建、58项单元测试、六组存储测试、单据页面/打印一致性和PDF分页独立校验均通过；60条混合行高销售/生产均5页，序号及文字边界校验通过。另发现已有标签回归断言不一致：`HEAD` 中标签字号已为19px，`tests/label-print-layout.cjs` 仍断言20px，因此该脚本失败。本次未更改标签样式或该断言。
